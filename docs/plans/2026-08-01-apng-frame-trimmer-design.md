# APNG 畫格修剪設計

## 目標與範圍

在動態貼圖頁面本次生成的 8 張 APNG 中，讓使用者可針對單張貼圖刪除開頭或結尾的錯誤畫格，不必重新抽取整支影片。第一版只處理仍在目前頁面記憶體中的結果；重新載入 Gallery 舊作品或上傳任意 APNG 後再拆幀，不在本次範圍。

修剪後至少保留 5 幀，以符合現有 LINE 畫格數檢查。總播放時間維持使用者原先選擇的 1、2、3 或 4 秒，重新分配剩餘畫格的顯示時間，避免產生 LINE 不接受的任意秒數。其他 7 張貼圖不受影響。

## 互動設計

每張結果卡新增「編輯畫格」按鈕。點擊後開啟單張編輯對話框，顯示 APNG 預覽、所有畫格的縮圖帶、開始與結束範圍控制，以及「刪除第一幀」「刪除最後一幀」「重設」「套用」操作。被排除的畫格會降低透明度，並即時顯示目前保留幀數。

範圍控制永遠保證至少 5 幀；達到下限時，刪除按鈕與不合法方向的控制會停用。取消只關閉對話框，不改變結果。套用成功後關閉對話框，卡片預覽、檔案大小、幀數、LINE 合規狀態、主圖製作器與聊天室選單圖製作器都立即使用修剪後資料。

## 架構與資料流

新增純工具 `frameTrimming.ts`，接收 `AnimatedStickerResult` 與起訖索引，切出 `sourceFrames`、使用既有 `encodeAnimatedPng` 重新編碼，並重算 Blob URL、大小、幀數、循環次數、透明度與動態狀態。工具拒絕少於 5 幀或空範圍，讓規則能由單元測試完整覆蓋。

新增 `FrameTrimDialog.tsx` 負責畫格選擇與 Canvas 縮圖，不承擔編碼或資料庫工作。`App.tsx` 接收套用結果、撤銷舊 Blob URL、只替換指定索引，並以既有 batch ID 呼叫 Gallery persistence，覆寫同一筆貼圖而不製造重複作品。智慧壓縮也同步把 `sourceFrames` 更新成實際採用的畫格，確保「先壓縮再修剪」仍然編輯目前版本。

## 錯誤處理與驗證

編碼失敗時保留原結果並顯示本地化錯誤。Gallery 寫入失敗沿用既有非破壞式提示，畫面上的修剪成果不回滾。測試涵蓋合法修剪、最少 5 幀、不合法範圍、metadata 更新、壓縮後 sourceFrames 一致性、UI 接線、Gallery 同 ID 覆寫與中英文翻譯。最後執行全量測試、TypeScript 與 production build。
